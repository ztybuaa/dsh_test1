# 0001 — 界面由应用自己渲染：用原生视图，不用画面流

**状态**：已接受
**日期**：2026-09-15

## 决定

侧边栏那一格里的浏览器，由**外壳自己渲染**成一块**原生视图**。**不采用**画面流（screencast / MJPEG）。

## 理由

网页能放的东西是一个**封闭清单**：网址（iframe/object/embed）、图片、视频、MediaStream、canvas。清单里**没有"另一个程序窗口"**。因此只要界面由网页渲染，一个真实浏览器进程就只能把**画面**搬进来——这带来一串无法绕过的后果：看不到真 DOM（不能选中、复制、右键、用输入法）、Agent 与人之间存在坐标换算、面板要自己实现输入转发与画面管线。

让应用自己渲染界面，就能把一个原生浏览器视图停在那一格里：**真渲染与可编程句柄两者兼得**。

已实测：那块视图在可编程层面以"页面"身份出现（带上下文标识），导航/读 DOM/点击三项全部通过——**包括插件工具真正使用的定位器点击路径**，且不需要任何逃生开关。

## 考虑过的替代

- **不透明源沙箱 iframe**：生态里已有实现，但内容跑在沙箱里、**无登录态**、被 `X-Frame-Options` 拒绝的站点直接显示原因面板，且 iframe 跑在用户自己的浏览器里，我们没有也不该有它的可编程会话。它给不了 Agent 任何东西。
- **同源反向代理 iframe + 注入脚本**：唯一能拿到"真 DOM"的网页方案，但工程最重、站点兼容性风险高。列为独立评估，不进入本项目。
- **继续用画面流**：被本决定否决。

## 后果

- 可以砍掉整条画面管线：帧流与限速、切标签兜底、面板→页面坐标换算、滚轮换算、输入转发、面板宽度→页面视口同步。
- 文本层不再需要：真 DOM 下选中/复制/无障碍天然可用。
- 面板↔视口同步不再需要：页面尺寸就是那一格的尺寸。
- **代价**：必须有一个渲染界面的宿主（本项目自建外壳）；插件不能只在纯网页环境下提供这一格。
