# 0002 — 插件领养已存在的视图，绝不新建页面

**状态**：已接受
**日期**：2026-09-15

## 决定

插件**不启动浏览器**，而是**领养**外壳里那块已存在的原生视图：连上外壳的可编程端点，找到该视图对应的目标并接管它。领养路径**必须假定目标已存在**，任何情况下都不新建页面。

既有实现中"自己 launch 一个浏览器"的路径保留为**没有外壳时的退化选项**。

## 理由

实测（Electron 44.3.0 + Playwright 1.62.1）：在 Electron 宿主上调用"新建页面"会直接失败，报 `Protocol error (Target.createTarget): Not supported`。因此"连上之后新建一个页面"这种写法在宿主下**必然抛错**——既有实现的附加分支正是这么写的。

另外，同一个应用里"DSH 界面窗口"和"浏览器视图"**都会以页面身份出现**，所以领养还要求能**确定性地认出**哪一个是视图，而不是靠猜。

## 考虑过的替代

- **连上后新建页面**：既有的附加分支写法；实测在宿主上直接报错，弃用。
- **按 URL 猜目标**：可工作但脆弱（页面会导航、多个目标可能撞车）。作为兜底，不作为首选；首选由外壳告知视图身份。
- **插件自己启动浏览器再想办法塞进窗口**：做不到——外部进程的窗口无法被放进另一进程的窗口里（见 ADR-0001）。

## 后果

- 视图契约必须包含**视图的身份**，而不只是一个端点地址。
- 会话模型需要一个"领养模式"，它的前置条件与"启动模式"不同（没有 launch 参数、没有档案目录参数）。
- 实测附加收获：断开连接**不会**关闭外壳应用，所以领养可以安全地反复断开重连。
- 实测附加收获：Electron 自己的 `webContents.getType()` 对原生视图报 `window`，而可编程端点报 `page`——两套词汇，实现时不要混用。
