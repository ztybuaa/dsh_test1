# 0016 — 这一格的缩放只有**一个**主子：适配；工具条空闲一行，同一句话只说一遍

状态：已接受（票 [#20](https://github.com/ztybuaa/dsh_test1/issues/20) 重新打开之后的那三条要求）
日期：2026-01-17（同 #20b 落地）
相关：ADR-0004（面板不渲染网页）、ADR-0013（面板驱动视图、缩放由外壳做）、
**ADR-0014（自动适配是外壳的活）—— 本 ADR 取代它的"决定三"**、ADR-0015（那一根上的界面）

## 背景

票 #20 落地之后用户真的开了外壳看实物，提回三条（票面最后一条评论，含他自己量到的证据）：

1. **"这个手动、自动我觉得反而是多此一举，直接自动就完事了。"** —— 去掉那一整套，永远自动；
2. 工具条**卡在两行**（他那台机器上 `61px = 34 + 26`，第二行是档位；`data-dsh-view-zoom-menu="open"`）；
3. 工具条第一行里**同一句话出现了两遍**：
   `BUTTON[data-dsh-view-zoom-menu]` 与 `SPAN[data-dsh-view-zoom][data-dsh-view-reading]` 都写着
   `手动 100%`。

## 决定一：缩放**没有**模式 —— 适配永远开着（取代 ADR-0014 决定三）

- 外壳里 `entry.zoomMode`、`modeCause`、以及四处闸门（`applyZoom` 写 `manual`、`requestFit` /
  `runFitPass` 的两处让位、`did-navigate` 的 manual 分支）**全部删除**。`zoomToken` 留着：它不是
  模式，而是"别用一份过期的计算覆盖一个刚到的新值"（ADR-0014 那条量出来的竞态）。
- **一次手动缩放（`−` / `+` / `reset` / 档位）只是"现在的值"**：下一次几何变化或换页会被重新适配。
  换页那一支就是原来 `auto` 那支（先回 100% 再适配），理由一字不变（响应式页面会停在上一页留下的
  百分比上）。**代价**：用户用 Ctrl+滚轮调过的缩放也不会被按回去了 —— 一个属性只能有一个主子。
- 面板那一侧：读数只剩百分比（`zoomReading(zoom)`），`auto` 按钮删掉，面板状态里连 `zoomMode`
  都不再存。

### "下一次几何变化"必须真的判一下（全量跑抓到的第二处）

把模式闸门删掉之后，**闸门的另一半作用没有人接手**：一次 `settle` 摆放、一次"同样的矩形再报一遍"、
宿主自己那一页刷新都会请一轮适配，而它们的矩形**根本没变**。票 #19 里它们被"人一按 ⇒ `manual`
⇒ 适配让位"挡着；删掉之后它们照着"按之前的算法"重算，把用户刚按下的值改回去（实测：`resetZoom()`
之后 400ms，页面已经回到 51.7%）。所以补两条**凭据**：

- `fitKeyOf(entry)` —— 视图现在占的那个矩形（`view.getBounds()`）的指纹。一次指名缩放把这个
  指纹"定住"；`requestFit` 遇到同一个指纹的摆放事件**直接返回**。例外只有 `view-navigation` /
  `view-load`（**视图那一页真的换页了**，票面原话"换页时也适配"）。
- `zoomToken` —— 请一轮适配的时候把代次记下来，真的开跑之前再对一次；对不上（这中间有人指名改过
  缩放）整轮作废。这条挡的是"一次拖动排下的**尾随**那一轮在用户按下 100% 之后才跑"。

### 兼容（票面明令不许破）

- **通道解析一个字没改**：`kind: 'zoom'` 与 `mode` 照旧接受、照旧校验。`mode: 'auto'` 现在的意思是
  "现在就重新适配一次"（旧客户端那颗「自动」、旧插件的 `{name, mode:'auto'}` 都走这一支），
  `manual`/缺省 = "把 `zoom` 按上去"。
- **发布出去的两个字段留着**：`zoom.json` 的 `mode` 与 `state.json` 的 `zoomMode` **永远是 `auto`**
  （旧插件在读它：`parseZoomReading` 里 `mode` 不是那两个词就整条读不动）。`modeCause` 删除 ——
  它存在的理由是分辨"启动时就是 manual"与"用户按过 100%"，而模式没有了之后那两件事本来就该一样。
- `VIEW_ACTIONS` 里的 `auto` 与端点 `desktop-view-auto` 留着（旧客户端仍在调）；面板不再渲染它。
- 工具给模型看的那句话里的 `(fitted to the pane automatically)` / `(set by hand)` 删掉：一个人刚按下
  150% 之后它仍会说"按栏宽自动适配的"，那是一句会说谎的话。

## 决定二：工具条**空闲严格一行**，展开之后三条路都能自己收

- 展开时工具条长高一行、面板矩形跟着下移（原生画面让位，ADR-0015 的形状不变）；
- 收法：**选一个档位**、**点到工具条以外**（`document` 的 `pointerdown`，捕获阶段，判据是落点不在
  工具条根节点里）、**`Esc`**（`document` 的 `keydown`，捕获 + `preventDefault`/`stopPropagation`）。
  两个听众只在菜单开着的时候挂着。
- 断言**读回几何**（工具条高度、被测量那一块的上边缘、外壳**应用**的落点 y），不读
  `data-dsh-view-zoom-menu` 这个状态变量。

## 决定三：那句话在工具条第一行里**只说一遍**

- 读数与档位菜单开关**合成一个 `<button>`**（它既是读数又是开关，真浏览器就是点百分比选档位）。
  诊断话术仍旧只在它的 `title` 与 `data-dsh-view-diagnostic` 上；用法提示搬到 `aria-label`。
- **重置按钮的标签从 `100%` 改成 `reset`**（title 不变）。这不是口味：读数去掉前缀之后就是 `100%`，
  标签为 `100%` 的它会在同一行里第二次说出那句话。动作一个没少（档位菜单里也仍有 100% 那一档）。
- 读回口：数**叶子节点文字**的出现次数（必须是 1），以及第一行里"像百分比"的叶子只有那一个。

## 后果

- 两条既有验收被**替换**（不是删掉）：`tests/fit-to-pane.spec.ts` 的"手动缩放优先"变成"手动缩放只是
  现在的值"，`tests/view-actions.spec.ts` 的"缩放跟着视图走、不跟着网站走"变成"换页之后决定权在
  适配"。两处的旧结论都是被 #20b 的**用户要求**推翻的，所以替换后的断言量的是新语义（并且反证过：
  回退修复就变红）。
- 读数的语义更窄了：`zoom.json` 里再也没有"这一格是不是被人碰过"这条信息 —— 按设计，今天
  "人碰过"与"适配算出来的"在读数上本来就该长得一样。
