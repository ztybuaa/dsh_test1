# 0005 — 继承既有项目的四项决定

**状态**：已接受（继承）
**日期**：2026-09-15

## 决定

本项目**继承**既有浏览器插件项目已经定死的四项决定，不重新论证、不推翻：

1. **元素定位用 accessibility 快照 + 数字索引 ref**——不让模型手写 CSS/XPath；只列出当前可见的元素（无渲染框或 `display:none` / `visibility:hidden` 的不进快照）；有状态元素带可选状态；导航后清空旧索引。
2. **快照保持紧凑，数据区另用"读正文"能力按需读取**——曾尝试在快照里附带完整可访问性树，实测单条快照膨胀到约 10MB、会话卡死，已回退。
3. **自动探测并继承系统代理**（显式配置 → 环境变量 → Windows 系统代理），本地回环一律 bypass。
4. **登录态首选持久档案**——专用持久档案目录跨会话保留登录态；启动时关闭自动化特征以降低被识别概率。

## 理由

这四项都是在真实使用中撞出来的，各自都有明确的失败经验在案（体积失控、站点限流/拒绝登录、外网打不开）。本项目换的是**界面渲染方式与通信方式**，与这四项无关。

## 与原决定的差异

第 4 项里"**用真 Chrome 承载**"这一条在本项目下**由外壳内的浏览器视图代替**：它的渲染器就是 Chromium，但**不带自动化特征**，因此"绕过站点对自动化的识别"这个目的以更强的方式达成，不再需要外挂一个真 Chrome 进程。持久档案与自动化特征这两条**不变**。

## 后果

- 既有项目的会话/快照/工具/代理实现与它们的测试（60+ 用例）是**起点而不是废料**。
- 既有项目的四份 ADR 是本次继承的依据，实现前应读。
- 计划中的"快照补位置尺寸"是在第 1 项之上的**扩展**，不是修改。
- 第 2 项的"按需读取"在 T5 落地为 `browser_extract`（页面 `innerText`，默认上限 20000 字符，超出即截断并把 `truncated` / `totalChars` 作为数据一起返回）；**快照仍然不携带正文**。
