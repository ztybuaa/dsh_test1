# 0004 — 面板落点是 DSH 第一方右栏的标签页系统

**状态**：已接受
**日期**：2026-09-15

## 决定

面板注册为 DSH **第一方右栏**的一个标签页类型：注册一个类型（身份、判别名、标题、优先级），并把该类型的 body 注册到右栏的标签页内容位。**不依赖**任何第三方侧边栏插件。

## 理由

第一方右栏本来就有一套完整的标签页系统：类型注册带优先级（外部类型默认最高，注释里明确"a tab type may ship from outside this repository"），body 按类型自己的身份注册，且**同一个类型的每个标签页、每个窗格（停靠或浮动）都由它渲染**。body 拿到的运行时信息里**已经包含"侧边栏是否展开"**——这正是把原生视图摆到正确位置所需要的输入之一。

既有实现把面板挂在第三方侧边栏插件上，并以"宿主浮层"兜底。那条路与本项目无关，也把插件绑在一个额外依赖上。

## 考虑过的替代

- **第三方侧边栏插件**：既有实现的落点；多一个依赖，且它的标签页语义不是第一方契约。弃用。
- **宿主浮层**：既有实现的兜底路径；不是"侧边栏那一格"。弃用。
- **自造面板**：重复第一方已有的停靠/浮动/分栏/持久化能力。弃用。

## 后果

- 面板 body 是一块**空白容器**：不渲染网页，只测量自身矩形与可见性并上报，同时处理被切走/折叠/浮动等生命周期。
- 原生视图的位置由**面板自报矩形**决定——不要求 DSH 提供任何"原生视图"专用 API（第一方目前也**没有**这类概念：全部第一方类型声明里 `webview`/`nativeView`/`BrowserView`/`WebContentsView` 零命中）。
- 拖拽分栏、缩放窗口、侧边栏折叠/浮动都要让视图跟随，这是本决定带出的主要实现负担。
