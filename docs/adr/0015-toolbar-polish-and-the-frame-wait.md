# ADR-0015 · 那一格上的界面：地址栏、标签标题、档位，以及"不要再等一帧"

状态：已接受（票 #20）
日期：2026-01-17（同 #20 落地）
相关：ADR-0004（面板不渲染网页）、ADR-0012（快照）、ADR-0013（面板驱动视图、缩放由外壳做）、ADR-0014（自动适配是外壳的活）

## 背景

票 #20 一次补齐了"这一格还不像一个浏览器"的五处缺口：**地址栏**、**标签标题**、
**读数清理**、**缩放档位**、**按钮跟手**（外加两条低优先的加载提示与悬停目标）。
其中四条落在同一层（面板那一半），一条落在会话里。这份 ADR 记的是**为什么是这几个形状**，
以及**哪些路被明确否决了**。

## 决定

### 1. 地址栏在面板里，走既有的那条 RPC；补协议的规则是"没有协议就补 `https://`"

- 输入框画在**面板**里（不是被驱动的那一页），所以它**不可能进快照** —— 这一点由
  `tests/panel-toolbar.spec.ts` 的"工具条存在时视图快照逐项不变"逐项读回（票面点名要的那条断言）。
- 它驱动视图走的仍然是**既有**的 `desktop-view-navigate`，
  **没有**为它动 `shell/preload.js` 一个字节：那条边界是"除矩形外什么都不许过境"，
  而地址栏够不到 Electron，也够不到视图。
- **补协议的规则**（票面要求"定一条规则并说明"，实现在 `src/toolbar.js` 的 `parseAddress`）：

  | 输入 | 结果 | 为什么 |
  |---|---|---|
  | `example.com` | `https://example.com` | 只写主机名 ⇒ 补 `https://`（今天的网站默认就是它） |
  | `localhost:3000` / `127.0.0.1:8080` / `[::1]:5173` | `http://…` | **唯一的例外**：本机上跑着的东西（夹具站点、开发服务器）几乎从不带 TLS |
  | `http://…` / `https://…` / `file:///…` / `about:…` | 原样 | 写明了就用它 |
  | `javascript:` / `data:` / `mailto:` / `blob:` | **拒**，并说清是哪一类 | 一条说不清的地址比一句"这个我不开"更容易骗人 |
  | 带空格 / 空 | **拒**，并说清 | 这一格**不搜索**（本期不做），所以不许把一句话悄悄变成一次搜索 |

  规则写在输入框的 `title` 上（用户读得到），也由 `tests/toolbar.spec.ts` 逐条钉住。
- 地址栏里那串字**跟着页面走**：每一次读回都把它对齐到 `url`，除非用户正在框里打字
  （正在打字时被冲掉是最讨厌的那种 bug）。证据：`tests/toolbar-panel.spec.ts` 的
  "跳转之后框里的地址跟着页面走"——**按的是「刷新」**，面板自己没有理由知道新地址。

### 2. 标签标题：用宿主**为"会变的标题"准备的那个座位**，不伪造

DSH 的标签条**允许**运行时改一个已存在标签的标题：座位 `sidebar.right.pane.tab.title`
在类型声明里就写着它是给"会变的标题"用的（*"A type with a live title … registers here and
reads its own store"*），产品自己的 Files 插件就是这么做的。于是：

- 本插件在 `apply()` 里往那个座位注册一个组件（key = 本插件的 `id`），它**取代**宿主在开标签
  那一刻抓到的 `title(address)`（那句话永远不会变）；
- 它读的是**一份共享读数**（模块作用域那个 `pageTitle`）：面板工具条每次读回都往里写；
- 标签在屏幕上时开一个 2 秒的心跳（**没有标签订阅时一次都不发**），因为换页不必经过这个面板
  —— Agent 走的是另一条路；
- 读不到就回落成类型自己的名字（"浏览器"），回落发生在**显示的那一刻**，不是一个存下来的默认值。

### 3. 读数只留用户要的：诊断话术**换通道**，不是删掉

票面原话：`nothing was changed` 是给开发者看的。于是：

- **用户可见**：`自动 78%` / `手动 90%`，必要时加 `加载中`（页面自己说它在加载）与
  `✗ <为什么没成>`（那是用户唯一能知道"这一按为什么没生效"的地方）；
- **诊断通道**：同一行元素的 `title`（悬停看得到）与 `data-dsh-view-diagnostic`（机器读得到），
  内容是宿主那句原话 + 视图现在在哪 —— 票面要求"诊断本身不要删"，一个字都没删；
- URL 从那行里**缩掉**：它的位置让给了地址栏（票面 C 的原话）。

### 4. 缩放档位：面板能要的只有那几个，宿主**自己**再收一次

点百分比给出一排标准档位（50/67/75/80/90/100/110/125/150/175/200），选一个走
`desktop-view-zoom-to`。两条约束：

- 每一个档位都必须在 `src/navigation.ts` 的 `ZOOM_STEPS` 里 —— 面板给出的档位与 `−`/`+`
  走过的那串数必须**是同一串**，否则"选了 125% 再按一次 +"会跳到一个谁也没见过的值上；
- 宿主**不信任**客户端说它规范化过了：`parseZoomPreset` 自己比对那张表，表外的一律拒。
  所以这条通道上**不存在**"缩放到任意值"这种通用命令（任意值是 Agent 工具那条路的）。

档位表在客户端与宿主各写了一份（客户端那一半是被 `scripts/build-client.mjs` 拼出来的自足脚本，
require 不到 `src/navigation.ts`），所以 `tests/toolbar.spec.ts` 从**两侧**各读一遍逐项比对 ——
与 `VIEW_ACTIONS` 那组名字用的是同一条规矩。

**菜单怎么展开**：刻意**不是浮层**。原生画面是一块 OS 级的视图，浮在面板矩形上，任何伸到工具条
下面的浮层都会被它盖住。所以展开时工具条**长高一行**，被测量的那一块自动变矮，外壳跟着把画面摆到
新的矩形上（面板的上报本来就跟着几何走）。证据：`tests/toolbar-panel.spec.ts` 读回
"关着时 34px、展开后更高、声明的高度是 `auto`"。

### 5. `settle()` 不再等一帧（票 #20 E 的核心）

**实测**（原始输出：`docs/research/t20-why-the-panel-button-waits-a-second.md`）：

| 一段 | 每次 |
|---|---|
| HTTP 往返 + 宿主 `displayState()` | **10–20 ms** |
| 外壳一次发布（含列举目标 0–2 ms、逐空间 `cookies.get({})` 0–1 ms，**三个空间也一样**） | **4–8 ms** |
| 外壳 `request.json` 轮询 | 12–137 ms（`SPACE_POLL_MS = 150`，刻意如此） |
| 插件 `state.json` 轮询 | ≤50 ms |
| **`settle()` 等 `requestAnimationFrame`** | **570–952 ms** ← 就是它 |

那一页在没有前台焦点 / 不被合成的时候几乎不出帧（实测 500 ms 里 0–1 帧，而页面上有一个一直在
排队的 rAF 回调），于是"等一帧"变成"等最多一秒"。

**所以 `settle()` 改成等那个真正的事实**：一次**同步强制布局**（读 `documentElement.scrollHeight`，
不经过合成器），再拿这一次的读数与上一次从页面读回来的那一份按比例对照；跟不上就在一个有界窗口
（1 s，每 10 ms 一次）内重试 —— **那个窗口不是延迟而是上界**，第一次就对上了就立刻返回。
改完实测：同一次按 **119–175 ms**（`tests/panel-toolbar.spec.ts` 的 `coldMs` / `warmMs`）。

上界取 1 s 不是随手写的：票前那个实现等的**就是**一帧，而这一页不被合成时一帧正好 ~1 秒，
所以最坏情况与票前**一模一样**，常态从 ~1 秒降到几十毫秒 —— 不会更差。
（第一版取 200 ms；整包连跑时 `tests/view-actions.spec.ts` 的 dpr 那一组在机器被占满的那一轮
红过一次，形状正是"渲染进程还没跟上"，所以放宽到这个不会更差的上界。单独重跑全绿、数字逐项正确。）

**票面点名不许用的四种"优化"，一种都没用**：没有调大任何超时、没有缩短任何轮询间隔、
没有为少一次往返去破 `preload` 边界、没有让面板直接够到 Electron API。

**顺带否掉了票面那条怀疑**：`cookieCount` 确实只用于展示，也确实在发布路径上 ——
但它实测是 **0–1 ms**（三个空间也是），挪走它省不下任何能解释 0.9 秒的东西。
按票面"只优化证实的大头"的规矩，**这条没有改**。

## 被否决的路

| 路 | 为什么不 |
|---|---|
| 给地址栏/档位单开一条命令通道（如新的 preload 消息） | `shell/preload.js` 的边界是这一层的立身之本；既有的 `/api` RPC 已经够用（ADR-0003/0013） |
| 档位菜单做成浮层 | 会被原生画面盖住（画面是另一块 OS 级视图，永远画在面板之上） |
| 标签标题用"某种运行时 API 去改" | 不需要：宿主**已经**为会变的标题留了座位，用它即可（伪造一条不存在的 API 才是错的） |
| 把 `settle()` 直接删掉 | 它挡的是"读到还没跟上缩放的视口"；删掉会让面板显示的读数可能属于上一个缩放。改成"等那个事实"而不是"等一帧" |
| 调大 `SpaceManager` 的 30 秒超时 | 那只是把症状盖住；本次**没有**动它，也没有为它下结论（见诚实清单） |

## 诚实清单（这一票没能验证到的）

1. **真 DSH 界面里的那一格渲染不出来**（首启流程要工作区 / API Key，ADR-0013 已记过），
   所以"侧边栏标签上**真的**显示页面标题"只验到**座位注册 + 组件输出**这一层
   （`tests/toolbar-panel.spec.ts`），"宿主标签条上那一格真的变了"这一步**没有**自动化证据。
2. 那 3 次"空间通道 30 秒超时"本轮**没能复现**（要复现得把机器真的占满），
   所以"它与那 0.9 秒同根因"这句话**没有被证实**，只是被否掉了票面那条具体的怀疑。
3. 没在"有前台焦点"的窗口里量过（本轮可见窗口的 `document.hasFocus()` 是 `false`）；
   §5 的原因描述以"不被合成时出帧掉到 1–2 Hz"这一实测事实为界。
4. 地址栏那条补协议规则只覆盖了列在表里的那几类；`ftp:` 之类既没实现也没有专门测过（一律拒）。
