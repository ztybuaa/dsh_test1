# 0012 — 快照多列一类元素：**可见 `<label>`，且它标注的控件没有被列出**

**状态**：已接受
**日期**：2026-09-16
**关联**：ADR-0001（元素只按 ref 定位）、ADR-0005（继承的四项决定，其中一条是"隐藏元素不进快照"）、ADR-0007（bounds 的来源）、ADR-0008（ref 钉住元素）、票 #10 第二条验收

## 背景

票 #10 要求"能把本地文件交给页面上的文件输入"。真实站点的常见形状是**把真 `<input type=file>`
藏起来、用一个好看的 `<label>` 触发**，而这条路上有一个死结（实测，见
`docs/research/dialogs-upload-download-iframes.md` 第 2 节）：

- 藏起来的 input 是 `display: none` ⇒ 没有盒子 ⇒ 不匹配 `:visible` ⇒ **不进快照**（这是
  ADR-0005 的继承规则，动它就是动那条规则）；
- 那个可见的 `<label for>` 匹配不到 `SNAPSHOT_SELECTOR` 里的任何一条（它不是
  `a[href] / button / input / select / textarea / [contenteditable] / [role=…]`）⇒ 它也没有 ref。

于是**页面上没有任何 ref 碰得到这次上传**：Agent 看得见那个控件、点不到它。同一形状在真实
站点里更常见的其实是**自定义样式的复选框/单选框**（隐藏真 input + 可见 label），那类控件今天
同样是"看得见却动不了"。

## 决定

**快照多列一类元素：可见的 `<label>`，当且仅当它标注的那个控件没有被快照列出。**

规则在**页面里、同一次求值里**判定，判据是"这个 label 的 `control` 在不在本框架这次匹配出来的
那批节点里"（按身份比较，不重新定义一遍"可见"）：

- label 标注的控件**已经在快照里**（绝大多数 label：复选框、文本框……）⇒ **不列**：控件自己就是
  该被点的东西，多列一个 label 只会让同一个控件有两个 ref。
- label 标注的控件**没被列出**（隐藏的 file input、隐藏的 checkbox）⇒ **列**：label 是页面上
  唯一能被点的东西，也是它唯一的 ref。
- 谁都不标注的 label（没有 `for`，里面也没有控件）⇒ **不列**：它不带任何东西。

选择器是**另一条**、单独导出的 `CONTROL_LABEL_SELECTOR = 'label:visible'`，
`SNAPSHOT_SELECTOR` 一个字符都不改。两条选择器各自的匹配数 + 该进的那一类 − 落在覆盖层里的
那些 == 快照列出的数，这条算术是它的守卫（见下）。

## 理由

**为什么是"通用规则"而不是"只认 file input"。** 让 Agent 点到"隐藏真控件的可见 label"这件事与
控件类型无关：文件选择器只是它最显眼的一种，自定义复选框是更常见的一种。把它写死成 `type=file`
会让另一半继续"看得见却动不了"，而两半的判据是同一个（"控件没被列出"）。

**为什么不把隐藏的元素塞进快照。** ADR-0005 的"隐藏元素不进快照"是继承的硬规则，而且它有实质
理由：快照列的是**能被作用的东西**，一个 `display: none` 的 input 不能被点击、不能被命中测试。
它那个可见的 label 能。

**为什么不改 `SNAPSHOT_SELECTOR`。** 那条选择器是"快照列的是引擎的 `:visible` 谓词说了算的东西"
这句话的凭据（T3、T8 都按它独立数一遍）。把 label 混进去会让"选择器匹配数 == 快照元素数"这条
既有等式在 `/snapshot` 上立刻不成立（那一页有一个标注可见文本框的 label，而它不该被列）。
两条选择器 + 一条精算的等式，比一条会被悄悄放宽的等式好。

**为什么判定必须在页面里。** "这个控件有没有被列出"只有拿**本框架这次的匹配结果**才能回答；
在插件侧重新查一遍会多一次可能与匹配之间隔了一次 DOM 变化的查询（ADR-0007 反对的正是这个）。

## 后果

- **封住了**：隐藏了真控件的可见 label 没有 ref 这件事 —— 文件选择、自定义复选框/单选框都包括。
  `browser_upload {ref, path}` 因此可以"点那个可见的 ref → 接住 file chooser → 交文件"，不必
  让模型手写选择器（ADR-0001 没有被打破）。
- **既有夹具页一个元素都没变**（有测试钉住）：`/snapshot` 上那个 label 标注的是**看得见**的输入框，
  所以它仍然不列，T3 那份逐项相等原样成立。
- **没有封住、也不要写成封住了**：
  - 一个标注隐藏控件的 label 与那个控件在无障碍树上仍是一对；快照里只出现 label 那一个 ref，
    `browser_type` 之类的动作打在 label 上是**没有意义**的（label 不是可输入的东西）——
    这类误用会由引擎以普通失败报出来，而不是在快照层面被拦住；
  - 框架里的 label 与主框架里的 label 是两条 ref（T9 的 frame 字段说得清谁是谁）。
- **代价**：快照在"隐藏真控件 + 可见 label"的页面上会多列若干条。这是有意的：那是页面上真正
  可点的东西，而它们此前是完全不可达的。
- 守卫跟着变强而不是变松：覆盖层里的节点**一个都不许**被列出来，两类选择器都查；把覆盖层做成
  一个 `<label for=…>`（指向隐藏控件）时这条守卫必须变红 —— 收集里那一步"覆盖层节点不进快照"
  是它的承重墙。
